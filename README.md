# Fruit API

Первый этап мобильного API по контракту API.md v5.3 из backend handoff. Базовый путь — /api/v1.

## Локальный запуск

```powershell
docker compose up --build -d
curl.exe -I http://localhost:8080/
curl.exe -i http://localhost:8080/api/v1/catalog
curl.exe http://localhost:8080/api/v1/config
docker compose logs api
```

OpenAPI доступен на http://localhost:8080/openapi/v1.json в локальной среде Development.
Контейнер использует HTTP на loopback. Для мобильного подключения по сети требуется HTTPS на внешнем прокси.

При старте EF Core применяет миграцию PostgreSQL. Dapper читает витрину и страницы новостей. Redis хранит каталог 30 секунд. Изменения каталога, внесённые напрямую в PostgreSQL, появятся после истечения TTL. Ответ каталога поддерживает ETag и условный GET. Ошибки API используют конверт мобильного контракта.

## Что доступно

- HEAD / для проверки сети.
- GET app/update, config, schedule и catalog.
- GET texts/{key}, news и news/{id}. Страница новостей сортируется по дате публикации и id.

Начальные записи — пустой каталог и расписание, тестовые настройки. Номер поддержки и условия в миграции предназначены для локального запуска. Для заполнения витрины обновите JSON в таблице storefront_content. Каталог, расписание, настройки и политика обновлений используют kind=singleton. Для текстов используйте kind=text и ключ документа в id. Для новостей используйте kind=news, id и published_at. JSON должен соответствовать контракту мобильного клиента.

Остались авторизация WhatsApp, профиль, адреса, геокодинг, корзина, заказы и QR-оплата, доставки, баллы, жалобы, уведомления, FCM и админка.

## Админка витрины

На сервере админка слушает loopback на порту 8082. Подключитесь через SSH:

```powershell
ssh -N -L 8082:127.0.0.1:8082 root@167.71.33.17
```

Откройте http://127.0.0.1:8082/admin. Логин — admin, пароль задаётся
переменной FRUIT_ADMIN_PASSWORD в серверном .env. Каталог, расписание,
настройки, тексты и новости редактируются в формате JSON мобильного контракта.
